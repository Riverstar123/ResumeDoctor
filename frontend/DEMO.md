## 正常样例

输入页「填入合成示例」与岗位页「填入示例 JD」直接使用 `docs/examples` 中的虚构材料。为两个岗位分别改名并保存、确认，方便观察报告是否串内容。

固定结果为 66.7，未知权重比例为 0.1667；Python 已满足、SQL 部分满足、Docker 缺少证据、本科学历已满足。这里只展示后端/fixture 结果，不在前端计算分数。

## 失败样例

在 mock 顶部选择「部分成功 / 仅评分」后新建两岗位诊断。第二个岗位应显示仅评分与具体模型错误，仍能展开评分和下载 Markdown，不能出现伪造的 AI 改写建议。

另选「提取失败」，发送一段合成经历。失败后点击「返回输入并重试」，确认原文仍在；切回正常场景再提交。选择「下次保存冲突」可验证用户编辑不会自动被覆盖。

## 真实联调与离线备选

- 真实演示按 `README.md` 启用 HTTP、配置公开处理告知，由服务端提供模型目录与凭证。保留真实调用证据与实际模型元数据。
- 离线备选使用 `npm run dev` 或 `npm run build:mock`，界面始终标注演示数据，不把固定样例当真实 AI 输出。
- 待 A/E 完成 REL-01、AI-03 后，再安排全组计时彩排并记录实际耗时、问题与修正；本分支未代替队友完成此验收。
