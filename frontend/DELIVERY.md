## A / M2 评审修复（2026-10-13）

A 在 PR #37 的评审中请求修改，提出两条 P2 缺陷及复现步骤。两条均已修复并补回归测试。

| 缺陷                                                                                                                                             | 原因                                                                                                   | 修复                                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新增岗位完成时会卸载正在编辑的 JD 编辑器，未保存草稿丢失，父组件 `dirty` 残留                                                                    | 完成回调无条件 `setEditing(id)`；`jobIds` 变化触发列表重载并清空 `jobs.data`，编辑器随之卸载           | 列表重载改为保留上一份数据（`useLoad` 的 `keepPreviousData`，仅岗位列表启用）；有未保存修改时禁止新增岗位；完成回调只在无脏编辑时切换，否则给出显式“跳到新岗位并放弃当前修改”的入口，并同步重置 `dirty` |
| 首次对话重试时重新读取最新版本，同一幂等键换了 `base_version`，服务端按 `docs/api/README.md` 返回 409 `IDEMPOTENCY_CONFLICT`，无法取回已受理任务 | `useAction.run` 保留幂等键，但回调在每次重试时重新读取 state；`IntakePage` 每次重试都重新 GET 档案版本 | `useAction.run` 增加一次性的 `prepare`，把 profile id、`base_version`、content、`model_id` 与 key 一同冻结到该次操作结束；网络重试重放完全相同的请求体，只有新操作才重新读取版本并换 key                |

新增回归测试（均已在未修复代码上确认会失败）：

- `tests/e2e/workflow.spec.ts`「unsaved JD draft blocks a new extraction and survives a running task」：有未保存修改时新增被阻止；任务运行期间产生的编辑不被完成回调清掉。
- `tests/e2e/http.spec.ts`「a retried first message replays the frozen body instead of the latest version」：合成 HTTP stub 按仓库幂等规则，在服务端受理并升版后丢弃响应；断言两次请求幂等键与请求体完全一致，且第二次发送前没有重新读取档案版本。
