# 五人分工与协作计划

## 成员与职责

| 成员占位 | 主责 | 交付物 | 第一评审人 |
|---|---|---|---|
| A（建议你） | M2 平台与集成；GitHub 带教 | API 路由、会话隔离、数据库、任务与集成 | C；共享契约由相关成员共同看 |
| B | M1 前端 | 输入、档案/JD 编辑、进度、报告、交互测试 | E |
| C | M3 输入与结构化 | 文件解析、对话建档、JD 提取、字段证据 | D |
| D | M4 评分 | 条件匹配、规则引擎、分项解释、固定测试样例 | C |
| E | M5 模型网关与报告；验收协调 | 假/真模型网关、结构化报告、Markdown 导出、验收记录 | B；网关由 C 加看 |

这不是“一个人写代码、四个人写文档”：每个人都拥有一块可运行模块并负责自己的验证。A 的集成工作较多，首轮先交付最小会话和假任务；E 负责组织全组验收来平衡工作量。

## 共享文件

- OpenAPI、数据库、contracts DTO、根配置：A 整理，变更影响谁就由谁评审。
- 评分规则：D 维护，C/E 校验语义。
- UI 全部由 B 维护。其他人提接口与展示需求，不直接大改页面。
- 数据库迁移只由 A 编号合并，避免多人生成冲突迁移。
- 各成员维护自身模块文档和测试；任何人发现契约冲突先记录，不自行改另一模块来“适配”。

## 四个相对里程碑

| 阶段 | 每个人做什么 | 退出条件 |
|---|---|---|
| P0 当前：文档 | 全员评审需求与契约；A 建仓库；各自认领 Issue | 五人理解流程、文档基线合并，用户同意开工 |
| P1 骨架与假数据 | A 会话/任务；B Mock 页面；C 假提取；D 手算评分；E 假模型/报告 | 全链路假数据演示，独立测试可运行 |
| P2 真实能力 | A 持久化/worker；B 编辑体验；C 文件/对话/JD；D 匹配；E 真模型 | 两条输入均能真实诊断，多 JD 独立输出 |
| P3 集成与演示 | 每人修自己问题；E 汇总验收；A 组织发布；B 演示页面 | 验收矩阵通过，README 命令能复现，演示材料完成 |

具体日期按课程 deadline 填写。不要五个人同时从空目录生成一套完整应用。

## 每日协作

每人用 3 句话更新 Issue：完成了什么、下一步是什么、被谁/哪个契约阻塞。需他人配合时链接 Issue 和字段，避免只在私聊约定。
PR 建议保持一个用户可验收变化；先 Draft PR 让队友看到方向。第一次每人先完成一个小文档 PR，走通同步、分支、提交、推送、评审、合并。

## Definition of Done

需求验收满足；接口/字段未漂移；模块测试与必要联调通过；异常状态有处理；无真实个人资料/密钥；对应文档更新；有队友评审；合并后 main 可运行（实现阶段）；Issue 记录验证证据后关闭。
