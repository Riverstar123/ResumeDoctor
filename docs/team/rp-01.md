## 关键设计

- **实现既有端口，不新增 HTTP 契约**：`ReportService` 实现 [ReportingPort](../../backend/app/contracts/ports.py) 的 `generate_report(profile_snapshot, job_snapshot, score_result, model_metadata, *, context)` 与 `export_markdown(item)`。M2 已有 `GET /api/v1/diagnoses/{id}/export` 并调用 `platform.reporting.export_markdown(item)`；本模块只提供实现，路由与错误映射留给 A。
- **冻结输入**：提示上下文只含已确认冻结的 Profile/Job 快照、`ScoreResult` 和固定提示词（`report-v1`）。生成前后比较 `score_result.model_dump(mode="json")`，任何变化都以 `MODEL_OUTPUT_INVALID` 失败；`ReportContent` 本身没有 score 字段。
- **输出先由结构、再由语义把关**：网关按 `task_output_schema("diagnosis_report")` 返回 JSON，服务再用 `ReportContent.model_validate` 校验 DTO。语义校验按 [06-ai-contract.md](../06-ai-contract.md) 与 [05-scoring.md](../05-scoring.md) 核对：要求与证据必须来自同一份冻结快照；`unmet→explicit_gap`、`partial→partial_gap`、`unknown→needs_evidence`；必答未达标项必须有 gap；`met` 不得有 gap；gap 证据必须是该条评分的子集；建议引用的原文必须是用户证据的逐字片段。
- **T18 不编造数字**：建议里的数字只能来自所引用证据的原文；无法支撑的具体成果必须使用 `[请填写真实数据]` 等占位模板并置 `requires_user_input=true`。阿拉伯数字、中文数量（`一百个`、`两倍`、`一年`、`一倍`）、逐位数字（`二〇二五`）、带万/亿的小数（`2.5 万`/`两点五万`）、跨亿/万整数（`一亿两千万`/`一亿零一万`）和中文百分比（`百分之五十`）先归一化为同一规范值再比较；百分比与普通数量保留类型，`50%`/`百分之五十`/`五十 %` 等价，但不能由 `50 个` 支撑，反之亦然；中文百分数后允许空白再跟 `%/％`；阿拉伯数字加万/亿或 `百分之…` 已消费的区间不再被中文扫描重复计数；`[请填写真实数据]` 等已知占位文本先移除后再检查。摘要若声称与 `ScoreResult.score` 不同的分数即失败，阿拉伯数字和中文分数（含小数，如 `六十六点七`）都参与核对，中英文句末标点（含 ASCII `.`）均可作为分数边界，但“评分一致/评分一般”等普通词语不会被当成 `1` 分，小数也不会被截成前缀。行动项只校验要求引用和 `task`/`done_when`。
- **T11 失败不掩盖评分**：网关错误（`MODEL_TIMEOUT` / `MODEL_OUTPUT_INVALID` / `PROVIDER_UNAVAILABLE`）原样上抛，由 M2 把该岗位降级为 `score_only` 并保留规则评分；导出仍输出评分、错误与“AI 报告未生成”，不编造分数。重试预算由 AI-01 网关统一为一次。
- **模型不可静默切换**：服务核对本次结果的 `model_id`、冻结的 `model_metadata.model_id` 与任务 `context.model_id` 三者一致；同一公开 id 的 `provider`、`model`、`prompt_version`、`gateway_config_version` 也必须与冻结快照完全一致（`generated_at` 除外），否则 `MODEL_UNAVAILABLE`。`prompt_version` 还必须是 `report-v1`。
- **不可信文本只当数据**：提示词明确简历/JD/评分理由均为不可信数据，不执行其中的指令；测试用注入文本确认分数与报告结构不受影响。
- **导出安全且可重复**：Markdown 中所有用户/模型文本经 `html.escape(..., quote=False)`；行内字段折叠换行，正文块保留换行。同一 `DiagnosisItem` 两次导出字节一致，并带岗位 id/版本、规则/匹配器版本、模型 id 与提示版本，便于 T23 与页面核对。
- **隐私过滤**：默认 fake 网关使用 `reporting/privacy.py` 的本地过滤（邮箱、手机、联系电话字段），被过滤到空的证据引用以 `[联系方式已过滤]` 占位；非 fake 网关必须显式传入已评审的 `privacy_filter`，否则在调用供应商前以 `PRIVACY_FILTER_REQUIRED` 失败。本地实现避免 M5 直接依赖 M3 目录，代价是规则副本需与 M3 同步，已列为交接项。
