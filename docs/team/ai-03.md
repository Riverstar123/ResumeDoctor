## 2026-10-30：A 第二轮复审 P2——变体队列隔离

A 在确认前三项已落实后，另复现一项 P2（CHANGES_REQUESTED）：real 模式 Playwright 同时启动 success/degrade 两套 API/worker，而两者原都连接固定 `rd_ai03_test`；生产 worker 的 claim 不区分启动器/上传目录，会领走另一变体任务。A 的独立反例（专用真实 PostgreSQL + 合成 DOCX + 交付的 `app.database/create_worker`，未触网）：uploads=B 的 API 上传产生的任务被 uploads=A 的 worker `run_once()` 实际领取，任务 failed/INTERNAL_ERROR；同文件新任务交 uploads=B 的 worker 则 succeeded。串领坏模型诊断时，正常 worker 还可能在保存评分前因模型映射不一致失败，拿不到预期 score_only。Playwright workers=1 只串行浏览器用例，不停另一套常驻 worker。已处理：

1. **按变体独立数据库（已修复）**：success 用 `rd_ai03_success_test`，degrade 用 `rd_ai03_degrade_test`，各自 API 与 worker 共用对应库及上传目录，队列物理隔离。启动器新增 `--db-name`（仅接受小写字母/下划线风格且含 test，拒绝任意外部输入），Playwright 配置按变体传库名。
2. **隔离回归（已补）**：[test_ai03_variant_isolation.py](../../backend/tests/platform/test_ai03_variant_isolation.py) 在一次性集群上建两个已迁移库，经**生产入口** `create_worker` 构造两 worker：先只向 success 队列入队，degrade worker `run_once()` 返回 False 且任务仍 queued，success worker 处理成功；再向 degrade 队列入队，反向同样断言。需要便携 PG（`RD_AI03_PG_HOME`/`RD_QA03_PG_HOME`），无 PG home 时 skip；不触网、不调供应商。
3. **联系方式正则 UUID 误报修复**：复跑 fake e2e 时暴露手机号正则在 UUID 十六进制段上误报（实测段 `144268871993` 含 11 位手机号样式数字，旧正则还允许 dash 分隔；此前通过仅为随机未命中）。`helpers-ai03.ts` 的两个正则加上两端边界（不邻接单词字符/连字符），经 6 组正反用例探针验证，真实手机号/邮箱仍检出。
4. 未改任何生产业务代码与契约；隔离回归在 fake 网关下运行。
