## 关键设计

- **单一入口**：`FakeModelGateway.generate_structured(task_name, prompt_context, output_schema, timeout_seconds, *, context)` 实现 [ModelGateway 端口](../../backend/app/contracts/ports.py)，四类 `task_name` 与能力名一致。
- **失败与预算**（[06-ai-contract.md](../06-ai-contract.md)）：单次调用超时即 `MODEL_TIMEOUT`；供应商 429/5xx（`provider_unavailable`）与非法 JSON（`invalid_json`）共用**一次**重试预算并短退避；输入超限直接 `INPUT_TOO_LONG`，不静默截断。常量 `RETRY_BUDGET=1`、`INPUT_LIMITS`（报告 20,000、提取 30,000）。
- **失败只来自服务端注入**：`failures` 由构造参数给出（`timeout`/`invalid_json`/`provider_unavailable`），用户经历、JD 或模型输出不会触发开关，与 `FakeTaskExecutor` 同一约定。
- **目录无密钥**：条目只含公开 id、显示名、provider、能力、实际模型名；返回的 `Model`/`ModelList` DTO（[contracts/models.py](../../backend/app/contracts/models.py)）天然没有 key/base_url 字段。默认条目 `demo-model-a`，沿用 API-01 的 id，避免 #13 集成时改变 B 的前端。
- **`resolve(model_id, capability, now)` 与 M2 `ModelCatalog` 同形**，供 #13 注入替换 [FakeModelCatalog](../../backend/app/platform/catalog.py)。
- **校验口径**：AI-01 的 fake 结果按冻结契约 DTO 校验（与 M2 `port_dto` 同一模式），`output_schema` 被要求是映射。按任意 JSON Schema 校验由 AI-02 的真实适配器交付。
- **调用记录**：`GatewayCall` 只保留 task_name、model_id、prompt_version、attempts、outcome、耗时、输入字符数，不记录原文、密钥或供应商回显。

## 执行说明（诚实记录）

- 本机原装 uv 为 0.12.18，工程 `required-version == 0.11.15`，因此执行了 `uv self update 0.11.15`；这会改动本机全局 uv 版本。
- 沙箱内 uv 下载 `ruff` 轮子长时间停滞，最终改用已下载的 `ruff-0.17.0-py3-none-win_amd64.whl` 经 `uv pip install` 装入 venv；其余依赖经 `uv sync --project backend --locked` 正常安装。
- 因 `uv run --frozen` 会重新同步并再次卡在 ruff 下载，测试与契约检查改用同一 venv 解释器直接执行（`backend/.venv/Scripts/python.exe -m pytest`、`-m app.tools.check_contracts`）。命令等价，但未走 `make` 包装。
- `ruff format` 只作用于本模块 4 个文件，未改其他文件。
