# QA-03 假模型端到端验收与缺陷收敛

日期：2026-10-28。对应 [Issue #26](https://github.com/Riverstar123/ResumeDoctor/issues/26)
（`[E][QA-03] 假模型端到端验收与缺陷收敛`），分支 `e/26-qa-03-fake-e2e`，执行人 E（y1324-cyber）。

## 结论与边界

本轮新增的 QA-03 真实栈浏览器套件 **8 项全部通过**：真实浏览器 UI → http 模式 Vite 同源代理 →
真实 FastAPI（SyntheticIntake 合成提取 + ScoringService 确定性评分 + FakeModelGateway 统一网关），
全程不使用浏览器 stub、不调用外部模型、不需要 PostgreSQL 或任何凭证。

- fake 范围内（T01–T21、T23 中不依赖真实模型/PostgreSQL 的部分）均有实测证据，结果见下表。
- **T22 真实模型 Web 演示不属于本轮**，按 Issue 明确留给 AI-03 的显式真实验收；本记录不声称其通过。
- **T14（worker 崩溃/租约接管）本机未执行**：本机无 PostgreSQL 且未安装 sqlalchemy extra，
  该条只能在 `make test-db` 的临时库上证明（`backend/tests/platform/test_jobs.py` 等），
  不以内存替身冒充；QA-02 于 2026-10-25 在迁移后的临时 PostgreSQL 上跑过完整 754 项（见
  [QA-02 最终记录](qa-02-final.md)）。
- T04/T15/T16 的 PostgreSQL 与文件清理侧由 A 的数据库集成测试覆盖；本轮在内存真实装配上
  验证了同一 HTTP/UI 契约（409、404 隔离、运行中删除后旧资源 404）。
- 本轮未发现需要新开缺陷单的 P0/P1：所有探测结果与 OpenAPI、评分契约及错误码约定一致。
  唯一“意外”是 SyntheticIntake 的内部码 `UNKNOWN_SYNTHETIC_INPUT` 在任务边界被按契约脱敏为
  `INTERNAL_ERROR`——这正是 M2 既有错误净化规则（`task_error` 只放行公开码集合），非缺陷。

## 本轮交付

| 文件 | 说明 |
|---|---|
| `backend/tests/e2e/fixture_app.py` | QA 专用装配：与 `app.integration` 同一条真实业务链路，故障只从 `RD_E2E_*` 服务端环境变量注入；无 `test_` 前缀，不被 pytest 收集 |
| `backend/tests/e2e/serve.py` | 变体启动器（success/partial/fail/slow），按端口自动设置 `ALLOWED_ORIGINS` |
| `frontend/playwright.qa03.config.ts` | 独立 Playwright 配置：四个后端（8010–8013）+ 四个 http 模式 Vite（5180–5183），独立产物目录 `test-results/qa03/`，workers=1 |
| `frontend/tests/e2e/qa03/*.spec.ts`、`helpers.ts` | 4 个变体共 8 个用例；两种输入路线、双 JD/五 JD、版本编辑、降级/全失败、运行中删除、契约复核 |
| `docs/07-testing.md`、`docs/08-development.md`、`frontend/README.md`、`Makefile` | 运行入口与范围同步；无 OpenAPI/数据库/评分契约变更 |

安全约束：故障开关只存在于后端进程环境（与 FakeModelGateway「失败只来自服务端注入」同一规则），
请求体、请求头和 JD/简历文本都无法影响它们；未知合成原文只会得到任务失败。
