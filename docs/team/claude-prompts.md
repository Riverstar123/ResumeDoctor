# 可直接使用的 Claude Code 任务提示

每位成员在自己克隆的项目根目录运行 Claude Code，使用自己的任务分支。先明确阶段和 Issue；不要要求“根据这些文档帮我把全站写完”。

## 文档评审（现在可用）

> 读取 CLAUDE.md、docs/00-decisions.md 和我的模块文档 docs/modules/M3-intake.md。我负责 M3，现在仅评审文档。检查我的输入输出能否与 M2/M4/M5 对接，列出冲突并修改本模块说明，不创建业务代码。如果需修改公共契约，请解释对消费者的影响并给出具体修改。

## 领取任务（以后开启实现）

> 读取 CLAUDE.md 和 docs/modules/我的模块.md。我负责 Issue #真实编号，验收条件为：粘贴 Issue 内容。先检查当前分支与已有改动，只实现这项任务。遵循 docs/api/openapi.json，使用合成数据和 fake 模型独立验证。结束时说明改动、执行的测试、待联调项。不要擅自更改其他模块或推送 main。

## 检查 Git 状态

> 请解释当前分支、哪些文件修改了、哪些未被 Git 追踪。不要删除或重置任何改动。帮我确认哪些文件属于当前任务，指出可能包含隐私或密钥的文件，不打印秘密内容。

## 提交 PR 前

> 对照本 Issue 验收检查 diff、接口兼容、异常处理、证据引用、测试和文档。区分已执行与未执行的验证。生成适合初学者阅读的 PR 标题和描述；我授权后再提交/推送当前任务分支。

## 队友评审

> 只审查这份 PR，重点找会让功能失败或破坏契约的问题，给出文件与原因。不要直接大改代码。检查是否修改了他人模块、迁移或依赖而未说明。没有实际证据就不要报错。

## 交接

> 总结当前任务已经完成的部分、修改的字段/接口、如何验证、阻塞点和下一步，将交接写入对应 Issue 或本模块文档。不得声称不存在的测试通过。
