# 决策记录与待确认事项

文档版本：0.1；状态：待团队评审的可开发基线。技术选型、人员和节奏属于提案，不表示用户已经确认。

## 已由需求明确

- 5 人协作，只有一人有 GitHub 基础，使用 Claude Code 辅助开发。
- 支持简历文件输入与自然语言对话输入。
- 支持多个 JD 和可选公司信息；提供评分、差距、修改建议、努力方向。
- 当前只做文档与仓库协作准备，不写业务代码。
- 项目级 `.claude/skills` 已安装 hr-resume-screening 参考包。
- 课程没有指定技术栈；必须把真实 AI 能力接入 Web，用户希望能切换不同模型。
- 用户自行创建/连接远程；本次只初始化本地 Git 并首提交 `init repository`。

## 默认提案（无课程限制时采用）

| 决策 | 默认值 | 原因 / 变更影响 |
|---|---|---|
| 架构 | 单仓库、模块化单体 + worker | 一套接口和数据库，降低五人联调成本 |
| 前端 | React + TypeScript + Vite | 单页应用，页面统一由 M1 管理 |
| 后端 | FastAPI + Pydantic + SQLAlchemy/Alembic | Python 数据处理，共享契约 |
| 数据库 | PostgreSQL，结构化快照用 JSONB | 保留版本，事务与任务恢复 |
| 身份 | 匿名 HttpOnly 会话 cookie | 课程 MVP 不做账号密码；不能跨设备找回 |
| 文件 | PDF 文字层、DOCX，最多 10 MiB、20 页 | 扫描件提示转文字；OCR 后续扩展 |
| 对话 | 非流式逐轮响应、可编辑结构化档案 | 降低聊天实时链路复杂度 |
| 模型供应商 | 暂不指定，统一网关、模型选择与开发用假模型 | 必须接入真实 AI，至少两种真实模型用于切换验收；供应商/预算待确认 |
| JD 数量 | 每次 1–5 个 | 限制成本，展示逐岗位比较 |
| 部署 | 先本地演示；公开部署另评审 | MVP 不默认承诺公网生产服务 |
| 排期 | 四个相对里程碑，无承诺日期 | 需课程截止日期后排日程 |
