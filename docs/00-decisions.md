## 业务日期与时间戳

档案截止月份、前端默认值/上限与提取提示中的当前日期统一按北京时间（Asia/Shanghai，UTC+8），不随浏览器或服务器的系统时区变化。后端共用 `app.business_calendar`，前端显式使用同一业务时区；M3 的 `today` 测试注入仍优先使用。

持久化时间戳、会话过期、worker 租约与任务截止继续使用 UTC。HTTP Cookie 的 Expires 在序列化前转换为 UTC/GMT，兼容数据库连接返回的其他时区。评分读取已确认快照的 `as_of_month`，不读取运行当天日期；此次统一业务日历不改写历史快照或评分规则。HTTP 字段、数据库结构及模型目录均保持原契约。

## 开发阶段规则

协作演练是 #2–#6。完成对应 PR 并合并后关闭任务。五项全部验收后 A 开始 SET-01；公共骨架合并后其他成员按依赖并行开发。创建 Issue 不代表已实现；关闭 Issue 必须附验收结果。
当前规划整理只修改文档和任务，不代替团队完成演练或业务开发。应用实现进度以 GitHub Issues、PR 和可执行测试为准。

## 变更管理

需求、接口、数据库和算法变化必须在同一 PR 说明原因、影响模块、兼容策略与验证，相关消费者审核。业务未知信息仍须保留 unknown，不能为使文档“确定”而编造简历事实。
