# 需求说明 PRD

## 目标与成功标准

帮助求职者看清“现有材料怎样对应目标岗位”，获得可追溯的诊断与可执行的改进计划。课程验收成功标准：两种输入都能完成全流程；同一档案可分析多个 JD；能解释每一条得分；五个模块可分别测试、按契约集成。
分数是当前材料的要求覆盖度，不是录用概率或个人能力排名。

## 用户主流程

1. 首次进入创建匿名会话，说明资料处理方式。
2. 选择上传文件或用对话描述经历；两条路径都形成一个档案草稿。
3. 用户检查教育、工作、项目、技能以及原文证据，可修改、补充；显式确认该版本。
4. 粘贴 1–5 个 JD，可分别填写公司信息。系统提取要求，用户检查原文对应关系、重要性与类别并确认。
5. 用户点击“开始诊断”。任务逐岗位评分、生成报告；页面轮询状态。
6. 展示每个岗位的分数、要求明细、已满足/部分/明确不满足/未知、差距、逐条修改建议和行动计划。
7. 用户补充资料后生成新版本，选择重新诊断；旧报告保留版本信息。
8. 可导出 Markdown 报告，或删除本会话全部资料。

## MVP 范围与验收

| ID | 功能 | 验收 |
|---|---|---|
| R01 | 上传 PDF/DOCX | 检查真实文件类型、10 MiB 限制；支持文字 PDF 与 DOCX；解析失败可改走对话 |
| R02 | 对话建档/补充 | 一次一轮，每轮最多 3 个针对性追问；提取事实保留用户原文；最终仍需确认 |
| R03 | 档案编辑与确认 | 保存产生新版本；未确认版本不能诊断；更改旧版本会被拒绝 |
| R04 | 多 JD 与公司背景 | 1–5 个岗位逐个结构化、确认；公司信息用于解释，不擅自计分 |
| R05 | 可解释评分 | 同一规范化证据及规则版本得分完全相同，每项有来源与状态 |
| R06 | 报告 | 每条差距关联要求 ID，每条事实关联证据 ID；不存在的成果只给待填写模板 |
| R07 | 异步与降级 | 超时、重试、部分成功有明确状态；模型报告失败仍显示确定性评分 |
| R08 | 比较与导出 | 并列显示独立岗位分数和未知比例，导出注明档案/JD/规则版本 |
| R10 | 模型选择 | 显示后端配置的可用模型，用户可选择；任务和报告记录实际模型；至少两种真实模型配置完成切换验收 |
| R09 | 会话隔离与删除 | 另一会话访问任意资源均 404；删除后旧 cookie 失效、任务停止写入 |

## 范围外

MVP 不做招聘方批量排名、自动投递、招聘平台抓取、面试/录用决策、转正画像、支付、团队管理、账号注册、OCR、旧 DOC、简历排版编辑器、PDF 报告导出。后续扩展另开需求，避免把安装包的所有能力当成交付承诺。

## 页面与状态

- 首页/输入页：文件选取、对话入口、格式限制、资料处理说明。
- 档案页：结构化编辑、原文证据、未知字段提示、版本和确认动作。
- 岗位页：JD 文本与公司背景、提取状态、要求编辑和确认；单个 JD 不得超过 20,000 字符。
- 诊断进度页：queued / running / succeeded / partial / failed，按岗位显示结果。
- 报告页：总分、按类别分解、要求明细、差距、改写建议、行动计划与导出。
- 全局：加载、空数据、重试、会话过期（401）、资源不存在（404）、版本冲突（409）、限流（429）。

## 输入限制与非功能要求

对话每条最多 8,000 字符、每会话最多 50 条用户消息；档案/JD 最大 100 条事实/要求；公司背景最多 10,000 字符；每会话每分钟最多 20 次写请求、最多 2 个并发任务。超限反馈具体原因。
提交任务目标 2 秒内返回任务 ID（本地验收，不包括模型等待）；单次模型调用 45 秒超时，规则见 AI 契约。总任务 5 分钟到期终止。性能数值是验收目标，尚未实测。
服务端保留匿名会话最多 7 天，无访问续期；原始上传解析终止后删除，最迟 24 小时；演示使用合成材料。

## 业务边界

只使用用户提供的信息。没有提到技能 = unknown；只有明确否认或可验证条件不足才是 unmet。姓名、性别、年龄、照片、籍贯、婚育不得用于匹配。JD 中不适合计分的个人属性要求标记为 ignored，并解释原因。
用户需要主动确认模型处理告知后才能上传/对话；是否向外部模型传输及供应商信息应在上线前填写。fake 模式明确标记演示数据；real 模式展示配置的供应商与处理说明。
